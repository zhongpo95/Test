# 카드부여·엘릭서 UI 적용 안내

장비강화의 흰색 패널, 청록색 강조선과 버튼을 두 탭에 적용했습니다. 상단 기본 메뉴와 로그, 왼쪽 탭, 오른쪽 유즈 일러스트는 기존 강화 허브를 사용합니다.

## 변경 동작

- 카드부여는 서버 연결이나 재료가 없어도 화면을 열 수 있습니다. 보유 재료와 필요 수량, 실행할 수 없는 이유가 표시됩니다. 조건 부족 시 시작 버튼은 회색으로 표시되며, 다시 누르면 조건을 재검사합니다.
- `부여 시작`에서 서버 연결, 장비 창 빈 공간, 카드 부여 재료(ID39)를 확인하고 1개를 차감합니다. NPC와 왼쪽 탭 모두 같은 화면 진입 경로를 사용합니다.
- 카드의 두 이로운 효과와 균열을 각각 10칸으로 표시합니다. 성공·실패·균열을 색과 기호로 구분하고, 달성 단계별 필요한 성공 횟수를 표시합니다. 완성한 카드는 `결과 받기`로 수령합니다.
- 엘릭서는 화면 열기와 초기 추첨을 분리했습니다. `연성 시작`을 누르면 동기화 이벤트에서 기존 3개 선택지를 추첨합니다. 선택한 효과 행과 선택지는 청록색으로 강조하며, 대상 선택이 필요한 경우 안내합니다.
- 탭 이동과 창 닫기는 현재 게임 세션의 진행 상태를 유지합니다. 처리 중에는 중복 실행을 막고, 닫은 뒤 도착한 응답·결과는 창을 다시 열지 않습니다. 결과를 받으면 다음 작업을 시작할 수 있습니다.
- 결과 수령 시 장비 창이 가득 차 있으면 결과를 보관합니다. 빈 공간을 만든 뒤 다시 받으면 됩니다. 게임 종료 후 미수령 결과나 진행 상황을 복구하는 영구 저장은 이번 범위에 포함하지 않습니다.
- 엘릭서의 실제 재료 요구·차감과 서버 거래 처리는 후속 작업입니다. 이번 단계에서는 기존 임시 연성 기능을 유지하며, 재료가 연동된 완성 시스템으로 표시하지 않습니다.

## 가져오기

1. `UI/UI_Stone.j`, `UI/UI_Elixir.j`, `UI/UI_Upgrade.j`, `content/NPC.j`를 함께 반영합니다. 기존 라이브러리 경로이므로 `Import.j` 추가 등록은 없습니다.
2. 아래 신규 텍스처 9개를 맵 가져오기 관리자에 추가합니다. 사용자 지정 경로는 `war3mapImported\UI_Upgrade_이름.tga`를 유지합니다. 정확한 경로는 `assets/upgrade/crafting/import-manifest.json`에 있습니다.

| 이름 | 용도 |
|---|---|
| Row | 흰색 효과 행·선택지 |
| Selected | 선택된 행·선택지 |
| Disabled | 실행 불가·처리 중 버튼 |
| StepEmpty | 미진행 칸 |
| StepSuccess | 성공 칸 |
| StepFail | 실패 칸 |
| StepRisk | 미진행 균열 칸 |
| StepPenalty | 발생한 균열 칸 |
| Lock | 봉인 표시 |

3. 기존 `UI_Upgrade_Panel.tga`, `Card`, `Action`과 허브 리소스가 필요합니다. 배포 ZIP에는 새 텍스처와 기존 강화 텍스처를 함께 제공합니다. 기존 사운드·스프라이트 모델·아이템 데이터는 맵에 남겨 두어야 합니다.
4. JN 에디터에서 맵을 다시 저장하고, 모든 참가자가 동일한 수정 맵으로 새 멀티플레이 세션을 시작합니다. W3X 자체는 수정하지 않았습니다.

## 재생성과 검사

Node.js와 `sharp`를 사용합니다. 별도 설치 위치라면 `SHARP_PATH`로 지정합니다. 상태 검사는 Node.js 기본 모듈만 사용합니다.

```powershell
node tools/build-crafting-assets.cjs
node tools/preview-crafting.cjs
node tools/check-crafting-state.cjs
```

SVG 원본·가져오기 목록·정적 미리보기는 `assets/upgrade/crafting`에 있습니다. 텍스처는 2의 거듭제곱 크기의 비압축 32비트 BGRA TGA입니다. 미리보기는 실제 JASS `Main`의 배치와 실제 TGA를 조합하며 동적 수치는 예시입니다. 게임 스크린샷이 아닙니다.

이번 검사에서 수행한 내용입니다.

- 정적 검토와 `git diff --check`, 텍스처 경로·형식·크기 검사.
- JassHelper 종료 코드 0, PJass `Parse successful` 및 종료 코드 0. 기존 검사 설정은 `24 errors ignored`를 함께 출력하므로 모든 진단이 0건이라는 뜻은 아닙니다.
- 카드부여·엘릭서·연성 결과의 정적 미리보기와 본문 영역 경계 검사.
- 실제 JASS 함수 일부를 모의 네이티브 환경에서 실행해 재료 차감, 조건 검사, 반복 입력, 진행 유지, 빈 공간 부족과 결과 수령, 두 모의 클라이언트의 초기 난수 호출 횟수를 검사했습니다. 이 검사는 전체 JASS 런타임·서버·멀티플레이를 재현하지 않습니다.

사용자가 게임에서 확인할 항목입니다.

- 서버 미연결·재료 0개에서도 카드 탭 표시, 조건 충족 후 시작 시 재료 1개만 차감.
- 카드 3줄을 끝까지 진행하고 결과 수령, 이후 새 카드 시작.
- 엘릭서 시작·대상 선택·재선택·봉인·결과 수령.
- 처리 중 다른 탭 이동 및 닫기·재진입, 두 플레이어 동시 조작.
- 결과 수령 전 장비 창이 가득 찼을 때 보관, 빈 공간 확보 후 1회만 지급.
- 16:9와 다른 화면 비율에서 긴 선택지·클릭 범위·상단 메뉴·HUD 복원 확인.

게임 실행, 실제 서버 저장, 멀티플레이와 게임 내 시각 검증은 이번 작업에서 수행하지 않았습니다.
