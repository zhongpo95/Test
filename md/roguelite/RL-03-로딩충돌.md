# RL-03 로딩 충돌 조사와 수정

> 최신 시험 맵은 시작 선택·상점 표시·스탯 배분을 수정한 [RL-04](RL-04-선택과배분.md)다. 아래는 RL-03 충돌 조사 기록이다.

사용자는 RL-02가 로딩 중 또는 직후 종료된다고 보고했다. 최신 `Errors/2026-09-19 21.26.37`의 Crash.txt, War3Log.txt, War3.dmp와 실제 RL-02 빌드 스크립트를 대조했다.

## 확인한 증거

- 덤프에 `Maps\mm\2\ARCRPG_RL_02.w3x`가 남아 있다. 설치된 RL-02의 SHA-256은 전달한 빌드 보고서와 같다.
- 충돌 스레드는 `0x6A14`, 예외는 `0xE0434352` 및 인수 `0x80004003`이다. 직렬화된 예외는 `System.AccessViolationException`, 관리 호출 기록은 `VirtualMachine__RunCodeHook`이다.
- x86 호출 스택에서 RunCode 인수의 바이트코드 주소 `0x3356FB38`을 복원했다. 해당 코드의 `CreateTrigger → FRAME 생성 → 크기 0.285/0.026 → 위치 0.018/0.552 → 우선순위 95 → 버튼 세 개` 순서가 `UIExpeditionCommon___Build`와 일치한다.
- VM의 CurrentOpcode 값은 `0x3356D7A0`이지만 그 주소의 코드 본문은 미니덤프에 포함되지 않았다. 따라서 최초 오류 명령이나 native를 덤프만으로 확정하지 않는다.
- 설치된 `dzclient_api.dll`을 실행하지 않고 정적으로 읽었다. `DzFrameSetEnable`은 RVA `0x19460`에 등록돼 있으며 null 확인 후 `FUNCTION_CControl__Enable`에 연결된 함수를 호출한다. 프레임 종류를 확인하는 분기는 없다.
- 새 `ExpUITexture`는 `BACKDROP`을 만든 뒤 이 컨트롤용 함수를 호출했다. 최초 공통 버튼 생성도 이 경로를 지난다. 기존 강화 UI의 배경 생성 경로에는 이 호출이 없다. 이를 이번 충돌의 유력 원인으로 판단하고 좁은 범위에서 수정했다.

덤프 SHA-256은 `8645936d79da421cf46352d550759d7cf16d1c2914568557128648a515cf1b04`, 분석한 Dz DLL은 `cb0f0c9b145d7a1c9e366733fc138af260f944fba2c95adf6664840e151457c0`이다. 개인정보를 포함할 수 있는 덤프 자체는 저장소에 추가하지 않는다.

## 수정

`UI/UI_ExpeditionCommon.j`의 `ExpUITexture`에서 BACKDROP에 대한 `DzFrameSetEnable` 한 호출을 제거했다. TEXT와 BUTTON의 활성화 처리, 카드 선택, 색상, 배치와 게임 규칙은 유지한다.

기존 모의 검사는 모든 프레임 종류에 Enable을 허용해 잘못된 호출을 검출하지 못했다. BACKDROP 호출을 거부하도록 검사 조건을 보완했으며, 수정 전 소스는 첫 UI 생성에서 실패하고 수정 후에는 기존 10개 UI 시나리오가 통과함을 확인했다. 이는 네이티브 충돌 재현을 뜻하지 않는다.

## 검증과 다음 확인

- 정적 검사. 덤프 호출 경로, DLL 바인딩, 현재 소스/호출자 대조 및 변경분 공백 검사 완료.
- 모의 검사. 수정 전 잘못된 호출 검출, 수정 후 UI 시나리오 10개 통과.
- 컴파일. JassHelper/PJass 종료 코드 0. 기존 `24 errors ignored` 출력은 유지된다.
- 전달 검사. 새 `ARCRPG_RL_03.w3x` 생성, 원본 자동 생성 함수 17개 및 기존 파일 2,380개 내용 보존, UI 리소스 14개 해시 검증. 상세 해시는 `RL-03-build-report.json`에 기록했다. 원본과 RL-02는 변경하지 않았다.
- 미수행. 실제 게임 재실행, 충돌 해소 확인, 인게임 클릭·시각 검사. 컴파일과 모의 검사만으로 크래시 해결을 확정하지 않는다.

다음 확인은 JN 환경에서 **ARCRPG_RL_03.w3x를 실행해 로딩 후 캐릭터 선택창까지 진입하는지** 확인하는 한 단계다.

## 공개 구조 정의 참고

덤프의 함수 인수와 바이트코드 구조를 해석할 때 [Script.cs](https://github.com/BlacklightsC/JassNative/blob/master/Cirnix.JassNative/JassAPI/Script.cs), [VirtualMachine.cs](https://github.com/BlacklightsC/JassNative/blob/master/Cirnix.JassNative/WarAPI/Types/VirtualMachine.cs), [OpCode.cs](https://github.com/BlacklightsC/JassNative/blob/master/Cirnix.JassNative/WarAPI/Types/OpCode.cs)를 참고했다. 공개 소스와 설치 DLL의 전체 버전 일치를 가정하지 않았으며, Dz 함수 바인딩은 설치된 DLL에서 직접 확인했다.
