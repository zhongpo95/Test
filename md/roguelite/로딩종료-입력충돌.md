# 로딩 종료 입력 충돌 조사와 수정

2026-09-20 사용자는 로딩 완료 화면에서 키나 마우스를 누르면 종료된다고 확인했다. 최신 오류 폴더 두 개와 JN 편집기의 마지막 컴파일 스크립트, 설치된 Dz DLL의 호출 경로를 대조했다. 맵 파일과 런타임 DLL은 변경하지 않았다.

## 확인한 증거

- `Errors/2026-09-20 11.00.02/War3.dmp`의 예외는 `0xE0434352`, 인수는 `0x80004003`이며 `AccessViolationException`과 JN의 `VirtualMachine__RunCodeHook` / `VirtualMachine__RunFunctionHook`이 기록돼 있다.
- 이 덤프의 입력 메시지는 `WM_KEYUP(0x0101)`, 키는 `TAB(0x09)`다. 저장된 함수명 인수 주소 `0x0b01f8b8`에서 `UIInfo2___TABKey`를 복원했다. 사용자 빌드에도 동일한 함수와 초기화 중 전역 키 등록이 있다.
- 직전 `Errors/2026-09-20 10.58.56/War3.dmp`는 Dz DLL의 반환 위치 RVA `0x1853f`와 그 호출자 `0x185b5`를 지난다. 설치 DLL을 정적으로 확인한 결과, 등록된 프레임 갱신 콜백을 실행하는 경로다.
- 두 번째 덤프에는 함수명 문자열 본문이 없으므로 이름을 직접 복원한 것은 아니다. 현재 소스와 사용자 빌드의 유일한 활성 `DzFrameSetUpdateCallbackByCode` 등록이 `FPS`라는 점을 대조했다. 이 함수는 인벤토리 이동 아이콘과 이모지 방향을 갱신한다.

덤프는 **오류가 발생한 콜백 진입 경로**를 보여 준다. 최초 메모리 손상 위치나 JASS VM 상태 이상이 시작된 시점까지 확정하지 않는다. 최근 대기시간·접기 버튼·체력 표시 변경을 원인으로 단정할 증거도 없다. 덤프 자체는 개인정보를 포함할 수 있어 저장소에 추가하지 않았다.

## 수정 범위

- `UI_InputGate.j`에서 로컬 플레이어의 영웅 선택 완료와 대상 프레임 생성을 기다린 뒤 전역 입력을 한 번 등록한다. 초기화 중 각 UI의 등록 함수를 예약하며, 트리거와 조건 핸들은 모든 클라이언트에서 같은 순서로 생성한다.
- TAB, P, I, K, O, M, 마침표, T 및 게임 HUD의 좌클릭·가운데 클릭 등 11개 등록을 이 경로로 옮겼다. 콜백 내부에서 조기에 반환하는 방식과 달리, 로딩 중 해당 전역 입력 콜백이 호출될 등록 자체를 미룬다.
- 영웅 선택 전에 필요한 선택창 휠과 기존 프레임 버튼 이벤트는 유지한다. 단축키의 키 값과 누름/뗌 구분, 원래 처리 함수도 유지한다.
- `FPS`의 Dz 프레임 갱신 훅을 0.03초 게임 타이머로 교체했다. 영웅 미선택, 이동 아이콘 미생성, 창 크기가 좌표 계산에 부적합한 경우 갱신하지 않는다. 기존 10초 후 시작 시점은 유지한다.
- 대기시간 두 배, 같은 위치에서 접기/열기, 몬스터 체력 표시는 변경하지 않았다.

## 검증

| 구분 | 결과 |
| --- | --- |
| 정적 분석 | 두 최신 덤프, Dz 호출 경로, 실제 컴파일 스크립트와 소스 대조. 변경분 공백 검사 통과. |
| 모의 실행 | `node tools/check-ui-input-startup.cjs` 6개, `node tools/check-expedition-ui.cjs` 13개, `node tools/check-expedition.cjs` 31개 그룹 통과. 실제 Dz 입력이나 게임 VM 충돌을 재현한 검사는 아니다. |
| 스크립트 컴파일 | JN의 최신 입력 스크립트 및 common.j/Blizzard.j를 사용한 JassHelper `--scriptonly`와 PJass 종료 코드 0. 기존 `24 errors ignored` 출력은 남아 있다. |
| 맵 생성 | 수행하지 않음. 임시 폴더의 스크립트 출력만 생성. |
| 런타임·시각 검사 | 수행하지 않음. 실제 로딩 종료 시 충돌 해소, 단축키 및 아이콘 표시, 멀티플레이 동작은 사용자 게임 테스트가 필요함. |

## 게임에서 확인할 순서

1. 수정 스크립트를 반영해 사용자가 직접 맵을 저장한다.
2. 로딩 완료 화면에서 TAB 키 또는 왼쪽 클릭으로 진입한다. 바로 입력할 때와 잠시 기다린 뒤 입력할 때 모두 확인한다.
3. 영웅 선택 이후 TAB/M/I 및 스킬 HUD Alt+클릭이 작동하는지 확인한다.
4. 인벤토리 이동 아이콘과 T 이모지의 마우스 추적을 확인한다.

다시 종료되면 새로 생성된 오류 폴더의 덤프로 이번에 막은 경로인지 다른 경로인지 구분한다. 컴파일·모의 검사 통과만으로 충돌 해결을 확정하지 않는다.
