## 같은 위치의 접기·열기 버튼

각 창의 오른쪽 버튼을 창 본문과 별도 부모에 두고 원래 좌표에 고정했다. 접으면 본문만 숨기고 같은 버튼의 문구를 `열기`로 바꾼다. 다시 누르면 기존 후보와 시간을 유지한 채 본문을 연다. ESC로 접을 때도 같은 버튼이 남는다.

다른 창으로 전환하거나 새 단계·개인 사건으로 넘어가면 접어 둔 상태를 정리한다. 선택·정비가 완료된 창의 열기 버튼은 사라진다. 강화창이 열리면 원정 본문과 토글 버튼을 함께 숨긴다.

## 몬스터 체력

원정 보스 생성 경로에는 기존 `BOSSHPSTART` 연결이 빠져 있었다. 생성 후 참여자마다 기존 보스 체력창을 연결했다. 원정 적의 보호막 최대값도 0으로 초기화하고, 기존 체력창이 보호막 없는 적을 갱신할 때 0으로 나누지 않도록 했다. 전투 중 상단 스탯 버튼을 왼쪽 빈자리로 당겨 보스 체력창과 겹치지 않게 했다.

일반 몬스터는 머리 위에 `100.0%` 형태의 체력 비율을 표시한다. 판정에 사용하는 `UnitHP / EnemyMaximum`으로 0.1초마다 갱신하고 이동하는 유닛을 따라간다. 원정 참여자에게 보이는 유닛만 표시하며, 사망·전투 종료 때 텍스트 핸들을 제거한다. 기본 워크래프트 체력바의 표시 설정에 의존하지 않는 추가 표시이며, 기본 체력바가 안 보이는 환경의 원인까지 확정한 것은 아니다.

## 검증

- 정적 검사. `git diff --check`, 버튼 부모·상태 전환·체력 표시 생성/제거 경로 확인.
- 진행 모의 검사. `node tools/check-expedition.cjs` 31개 묶음 통과. 대기 만료 직전/직후, 사건 별도 시간, 일반 적 체력 갱신·가시성·정리, 참여자 보스바 연결과 보호막 없는 보스 체력창의 산술 검사 포함.
- UI 모의 검사. `node tools/check-expedition-ui.cjs` 13개 묶음 통과. 같은 버튼 반복 클릭, 위치 유지, 강화창과 전환·확정 시 표시 정리 포함.
- 스크립트 컴파일. 기존 원본 배치 scaffold로 JassHelper `--scriptonly` 및 PJass 종료 코드 0. 기존 기준선의 `24 errors ignored` 출력은 유지된다.
- 전달 범위. 스크립트·검사·문서만 수정. `.w3x` 생성·교체·패키징 없음.
- 미수행. 실제 게임의 버튼 입력과 렌더링, 체력 글자의 가독성·위치, 실제 멀티플레이. 프레임/텍스트 네이티브는 모의 검사이므로 인게임 확인이 필요하다.

## 다음 인게임 확인

1. 선택과 상점의 제한시간을 확인한다. 오른쪽 버튼을 누른 위치에서 마우스를 옮기지 않고 다시 눌러 창이 열리는지 확인한다.
2. 일반 몬스터를 공격해 머리 위 체력 비율이 줄고, 죽으면 표시가 사라지는지 확인한다.
3. 보스전에서 기존 보스 체력창이 나타나고 공격에 따라 감소하는지 확인한다.
