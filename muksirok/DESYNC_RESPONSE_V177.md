# v171 단독 이탈 대응과 v177 검증 계획

## 확인된 문제

2026-09-24 00:13:21의 사용자 자동 리플레이에 Desync(0x23)가 기록되어 있다. 연결 분리 후 종료할 때 발생한 Game.dll+0x122C57 접근 위반과 구분한다. 불일치를 최초로 만든 게임 함수는 아직 특정되지 않았다. 1번 캐릭터는 사용자 확인에 따라 칼리오스트로이다.

## 실행한 대책

- 기존 퇴장 로그에 important를 지정하여 일반 boot 항목 1600개 제한 이후에도 남긴다.
- 별도 Desync 순환 로그에 실제 빌드 버전, 설치 시각, 플레이어 퇴장 전후, 게임 자체의 패배 요청을 보존한다.
- 5초마다 기존 진단 타이머를 사용해 모든 슬롯을 기록한다. 선택 해제·영웅 부재도 기록하며, 유효 영웅의 체력·마나·좌표·스태미나·현재 명령·인벤토리 종류와 사용 횟수를 읽는다. 라운드 전환 전후에도 같은 상태를 기록한다.
- UI 동기 메시지의 발신 슬롯·원문·처리 BEGIN/END를 별도 UISync 로그에 남긴다. 새로운 동기 패킷이나 게임 타이머는 추가하지 않는다.
- 수집 스크립트는 가장 최근 v177 기록의 플레이어 번호를 골라 해당 슬롯 로그와 최근 리플레이·오류 자료를 별도 ZIP에 복사한다. 원본을 삭제하지 않는다. 시각 조건은 다른 판 자료를 완전히 배제하는 보장이 아니므로 분석 시 버전·시각·상태를 다시 대조한다.

## 다음 실제 플레이에서 확인할 내용

세 사람 모두 같은 v177 MP 파일을 사용한다. 이탈이 재현되면 게임을 새로 시작하기 전에 세 사람의 로그와 LastReplay.w3g를 보존한다. 정상 플레이어의 리플레이도 필요하다. 수집 스크립트는 각 PC의 경로가 다르면 LogDirectory와 WarcraftDocuments를 지정한다.

리플레이의 첫 Desync/Leave 시점에 맞춰 Desync 상태와 UISync 수신을 비교한다. 맵의 패배 요청이 있었는지, 어떤 슬롯이 먼저 제거됐는지, 공통 UI 메시지의 실행 순서·결과 상태가 처음 달라지는 지점을 확인한다. 차이를 만든 호출이 확인되면 그 경로만 수정하고 동일 조건의 다인 플레이로 검증한다.

## 검증 범위와 남은 한계

Lua 모의 실행에서 미선택/부재 영웅, 중요 이벤트, UI 메시지 줄바꿈, 실제 버전 경로, 진단 예외 격리를 확인했다. 수정 Lua 파일의 구문도 검사했다. 맵 빌드와 복사본 해시 확인은 전달 검증이다.

실제 Warcraft 실행, 3인 재현, UI 표시 및 추가 기록의 디스크 부하 검증은 수행하지 않았다. 이 빌드는 원인 추적용이며 Desync가 해결됐다고 주장하지 않는다. 상태 표본은 전체 엔진 체크섬을 대체하지 않는다. 기록이 없는 짧은 시간 구간에서 발생한 변화는 추가 계측이 필요할 수 있다. 코드가 예외를 보호하더라도 디스크 쓰기가 느리면 실제 플레이 지연이 생길 수 있다.
