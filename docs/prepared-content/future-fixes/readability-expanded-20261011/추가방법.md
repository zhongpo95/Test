# 전체 사건 가독성 편집 추가 방법

이 폴더는 승인된 대표3건의 편집 방식을 전체 작성 사건 본문으로 확대한 준비본이다. 실제 게임이나 기존 테스트에는 적용하지 않는다.

## 범위

- 기존 머리카드28종의 작성 사건879개, 공통 사건13개, B3종의 작성 사건74개를 합친966개다.
- 수정 대상은 events[].story의 공백·줄바꿈과 별도 강조 메타데이터다.
- world.intro, 선택지 label/result, 카드 설명과 보상·조건·수치는 이번 대량 편집 범위 밖이다.
- 생성기가 만드는 추가 입문 사건은966개에 포함하지 않는다.
- 승인된 대표3건은 동일 원문인 경우 그대로 우선한다.
- 움직임은 승인한 렌지 대사 일부만 비교 화면에서 선택적으로 확인한다. 모든 사건에 효과를 추가하지 않는다.

## 원본과 결과

drafts.json은 원본 경로·파일SHA·본문과 초기 문단 초안을 담는다. structured-requests와 structured-responses는 작품별 Gemma 요청·원응답이다. proposal.json은 유효성 검사와 수동 강조 교정을 거친 편집안이다. validation.json에서 reviewedWorlds=32이고 proposal.json의 status가 prepared_not_applied인지 확인한 뒤 사용한다. 진행 중 파일은 최종본으로 적용하지 않는다.

editor-overrides.json에는 위험과 단서의 구분, 불필요한 강조 삭제 등 사람이 선택한 후속 판단을 남겼다. rejected.json에 원문 불일치·불필요한 마지막 문장 경계·교체된 강조를 보존한다.

## 이후 실제 적용

1. 최신 소스 파일 SHA와 사건 key·before를 모두 확인한다. 기존 미래 교정87필드 등 내용 편집을 먼저 적용했다면 SHA가 달라지므로 이 준비안을 그대로 덮어쓰지 않는다. 바뀐 본문에 문단·강조 검토를 다시 수행한다.
2. 동일한 원문인 사건의 story만 업데이트한다. 본문에서 공백을 제외한 모든 글자와 순서가 같아야 한다. 현재 원본에는 문자 그대로의 역슬래시+n과 실제 줄바꿈 표현이 있으므로 생성기의 줄바꿈 처리에 맞춰 변환하고 비교한다.
3. highlights는 엔진이 현재 해석하는 태그가 아니다. JSON에 색 태그를 무작정 끼워 넣지 않는다. 표시 코드에서 구절과 역할을 연결하는 구현을 별도로 검토한다. 기존 자동 이름 강조와 중복되지 않게 해야 한다.
4. 행간·문단 간격은 HTML 비교값을 그대로 게임 좌표로 복사하지 않는다. 실제 폰트·패널 폭에 맞춰 긴 사건의 줄 수와 선택지 위치를 확인한다.
5. 움직임은 실제 구현 시 표시 중인 해당 구절에만 제한하고 화면을 닫으면 갱신을 중단해야 한다. 현재 준비본은 이 기능의 Warcraft 구현이나 부하 검증이 아니다.
6. 별도 작업 브랜치에서 생성·컴파일·실제 화면 검사를 거쳐 main 대상 PR로 전달한다. 이 단계에서는 맵·ASI를 만들지 않는다.

## 검사 경계

파일 해시, 사건 누락/중복, 공백 외 문자 동일성, 강조 구절 존재, 브라우저용 스크립트 구문을 검사한다. 원작 사실 검증을 새로 수행하는 작업이 아니다. HTML 시각 확인과 Warcraft/JN 런타임 검증 여부는 최종 검토결과에 별도로 적는다.

첫 대량 검토가 긴 사건까지 한 문단으로 합친 제안은 채택하지 않았다. 원응답은 rejected-first-pass와 최종 copy_archive 보존본에서 확인한다.
