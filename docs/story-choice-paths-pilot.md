# 선택 개방 서브와 짧은 이야기

2026-10-31. 참조 대화 `01a1895c-b382-7f32-ab8e-120d3699b62e`와 이후 사용자 수정 지시를 반영한다.

## 현재 동작

- 전체 28개 작품에 메인 대답으로 열리는 서브가 있다. 기존 연결과 신규 연결을 합쳐 후속 사건 164개를 활성화했다. 새로 작성한 21개 메인 연결은 `story-choice-links.md`에 기록했다.
- 선행 대답이 없는 독립 서브 327개는 보유 작품의 메인을 마치고 다음 머리를 고를 수 있을 때 후보로 등장한다. 공통 서브도 이 목록에 포함한다. 미보유 작품, 필요한 카드, 후일담의 완주 조건은 그대로 검사한다.
- 머리 선택 목록은 다음 머리와 서브를 섞어 3개씩 표시한다. 후보가 3개 이상이면 마지막 페이지도 순환하여 3개를 유지하며, 한 페이지에 같은 후보를 중복하지 않는다. 총 유효 후보가 1~2개라면 존재하는 후보만 표시한다. 페이지 이동은 무료다.
- 사용자가 말한 3개 제한은 머리 선택 화면에만 적용한다. 진행 중인 일반 메인의 갈림길은 기존처럼 다음 메인과 열린 후속을 최대 4개까지 함께 표시한다. 각 사건 안의 대답과 보상은 삭제하지 않는다.
- 머리 선택 화면에서 서브를 고르면 그 사건부터 시작하는 짧은 이야기에 들어간다. 빈 머리 한도가 있어도 이 이야기의 선택 경로가 끝날 때까지 새 머리를 제시하거나 획득할 수 없다. 한 사건짜리는 최종 정산 때 종료하고, 후속이 열리는 연계는 그 후속을 마칠 때까지 이어진다. 모든 분기를 동시에 수행하는 방식은 아니며 선택한 경로에 후속이 없으면 그 경로가 종료된다.
- 짧은 이야기는 머리 슬롯을 소비하거나 완료 시 머리 한도를 더 늘리지 않는다. 기존 서브의 비용과 보상 수치를 유지한다. 완료 후 다시 머리·남은 서브 목록으로 돌아간다.
- 일반 메인 진행에서는 실제 사건을 고를 때 다른 열린 후속 기회를 포기한다. 독립 서브는 단순히 목록에 보였다는 이유로 포기 처리하지 않는다. 이미 완료한 사건은 다시 나오지 않는다.
- 폐지한 재추첨/휴식 요청은 자원·기회를 바꾸지 않는다.

## 출발 선택

`Data/Data_Expedition.j`의 `PROTO_TEST_START_HEAD = 0`으로 테스트 고정을 해제했다. 출발 머리는 사용자가 직접 선택한다. 페나코니 경로를 테스트하려면 출발 화면에서 페나코니를 선택한다.

페나코니 메인 4장 두 번째 대답의 최종 정산 뒤 「서로 다른 얼굴의 안내인」을 연다. 비용은 4이다. 이 서브의 두 번째 대답은 비용 6의 「기억에 남겨 둔 출구」를 연다. 서브 진행 중 메인 5장의 진행도는 그대로다. 서브 대신 메인을 선택하면 열린 서브를 포기한다.

짧은 이야기 잠금 시험은 후유키 메인 완주 후 「학교에 남은 마법진」을 선택하고 첫 대답으로 「서로 다른 마력의 흔적」을 여는 경로로 검증했다. 후속 완료 전에는 머리가 없고, 완료 후 머리·서브 후보 3개가 돌아온다.

## 상태와 원고 추가 방법

- `ProtoSideState[ProtoStoryKey(pid,id)]`는 0 잠김, 1 개방, 2 포기, 3 선택이다. 기존 사건의 성공/실패 대답 이력과 분리한다.
- `ProtoActiveSideStory[pid]`는 머리 선택에서 시작한 짧은 이야기의 입구다. `ProtoOpenSideCount[pid]`가 최종 정산 후 0이면 선택한 경로가 종료되어 잠금을 해제한다.
- 후속은 `choicePath: true`, `previous`, 양수 `previousChoice`로 연결한다. 한 대답에서 최대 3개까지 열 수 있다. 생성기는 분기별 첫 후속/다음 후속 포인터와 개방 안내를 만든다.
- 독립 서브는 `headChoice: true`로 지정한다. mainStage, previous, choicePath와 동시에 사용할 수 없다.
- 기존 본편 결과와 보상 수치를 유지한다. 새 연결은 맵의 선택 구조이며 원작의 공식 퀘스트라고 주장하지 않는다. 원고 검토 시 인물의 등장 시점과 장소를 함께 확인한다.
- `node tools/generate-prototype-content.cjs`로 JASS를 갱신하고 `--check`로 일치를 확인한다.
- 개방은 대화의 마지막 정산에서만 일어난다. 초기 대답, 후보 갱신, 오래된 동기화 요청, AP 부족은 상태를 확정하지 않는다.
- 후보 제한시간 만료는 사냥으로 돌아갈 뿐 기회와 짧은 이야기 잠금을 유지한다. 두 번째 성장에서도 잠금·개방·포기를 유지하고 행동력만 100으로 채운다. 새 원정에서 모두 초기화한다.
- 보상 정산은 연결된 후속만 조회하고, 머리 선택 가능 판정은 보유/완료 수를 사용한다. 후보마다 전체 머리를 반복 조회하지 않는다.
