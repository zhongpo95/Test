# 사건 본문 줄 진단 v1

## 적용과 실행

UI/UI_ExpeditionPrototype.j를 적용한다. 신규 임포트 파일은 없다. 맵과 ASI를 생성하지 않는다. 기존 사건 표시와 보상 처리는 유지한다.

1. 사건의 행동 선택 화면을 연다. 커서를 오른쪽 선택지에서 벗어나게 둔다.
2. 채팅에 `-줄테스트`를 입력한다. 0~3번 플레이어가 사용할 수 있으며 입력한 플레이어에게만 표시한다.
3. 비교 창의 빈 줄 0/1/2개를 한 화면으로 촬영한다.
4. F12 로그에서 `줄 진단 v1`, T1 534 원문/처리, T1 133 원문/처리, T2 현재 원문/프레임 스냅샷을 확인한다. 줄바꿈 토큰은 `/N/`으로 출력한다. 긴 로그는 여러 화면으로 촬영해도 된다.
5. 닫기 버튼 또는 `-줄테스트` 재입력으로 닫는다. 다시 열면 로그를 새로 읽는다.

## 판정

- 534 처리에 `한다./N//N/그러나`가 있는지 확인한다.
- 133 처리에는 기존 `/N//N/` 대신 `/N//N//N/`가 있어야 한다.
- T1은 실제 JN 네이티브를 사용한 함수 결과이고 T2는 명령 입력 순간의 프레임 문자열이다. 서로 다른 사건의 T1/T2를 동일 원문으로 비교하지 않는다. T2의 색상 태그는 PaperText에서 보정되므로 줄바꿈을 비교한다.
- T3 비교 창에서 빈 줄 0/1/2개가 서로 다른 높이로 보이는지 확인한다.
- 진단은 사냥이나 사건 타이머를 멈추지 않는다. T2는 입력 순간의 스냅샷이므로 시간이 지나 사건이 넘어간 화면과 혼동하지 않는다.
- 문서의 bytes 값은 StringLength 반환값이다. 정확한 런타임 문자열 단위 판단도 진단 대상이다.

이 테스트는 행간 개선 패치가 아니다. T4 높이 측정과 줄 분할, TEXTAREA 실험은 넣지 않는다. 게임 결과를 확인한 뒤 다음 구현을 결정한다.

## 검사 결과

JASSHelper/PJASS 통과(기존 억제 진단 24개). 진단 로컬 격리/문자열/본문 읽기/닫기/재사용 모의 검사와 기존 UI 모의 18개 그룹 통과. 실제 게임의 표시·클릭·멀티플레이 검증은 미실행이다.
