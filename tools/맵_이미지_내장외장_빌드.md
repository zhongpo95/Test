## 재빌드

Python 3와 같은 비트수의 StormLib.dll이 필요하다. Pillow는 이 패키징 단계에 필요하지 않다. `content/modelpack-manifest.json`이 관리 대상 1,749개 경로·바이트·해시와 팩 버전을 기록한다. 다른 버전 이미지로 변경할 때 목록의 해시도 함께 갱신하고 해당 ASI와 배포한다.

```powershell
python tools/build-map-assets.py --map "기준맵.w3x" --assets "D:\Work\ARCANA\builds\asi\20261013_card_art_uniform\images" --manifest content/modelpack-manifest.json --stormlib "StormLib.dll" --output "새내장판.w3x" --mode embedded
python tools/build-map-assets.py --map "새내장판.w3x" --assets "D:\Work\ARCANA\builds\asi\20261013_card_art_uniform\images" --manifest content/modelpack-manifest.json --stormlib "StormLib.dll" --output "새외장판.w3x" --mode external
python tools/check-map-assets.py --stormlib "StormLib.dll"
```

외장판은 목록과 일치하는 이미지 파일만 제거한다. 제거 대상 파일의 해시가 다르면 중단한다. 맵 임포트 목록도 모드에 맞춰 갱신하며 다른 항목은 보존한다. 동일한 이미지 폴더를 기존 ASI 제작기로 패키징하면 된다. 출력 파일이 이미 있으면 덮어쓰지 않는다.

내장판은 이 이미지용 Arcana_A.asi를 따로 배포할 필요가 없다. 검증할 때는 게임 종료 후 기존 Arcana_A.asi를 로드 위치 밖으로 임시 보관해 내장 이미지만으로 표시되는지 확인한다. 다른 용도의 플러그인까지 제거하는 지시가 아니다. 파일을 자동 설치하거나 기존 ASI를 이동하지 않았다.

## 검증과 제한

- 이미지 1,749개 및 기존 비관리 파일 2,570개를 StormLib로 다시 읽어 바이트 해시를 검증했다. 스크립트·지형·오브젝트 데이터는 원본과 동일하다.
- 해시 테이블을 대조하여 목록 누락과 로케일 변형을 차단한다. 기존 맵의 File숫자 이름을 StormLib 쓰기 API가 임시 이름으로 오인하므로 전용 MPQ v0 작성기를 사용하고 독립 StormLib 디코더로 검증한다.
- 4,096바이트 섹터 경계, 빈 파일, 비압축/압축 데이터, File숫자 파일명, 불완전 목록 거부 회귀 검사 통과.
- 내장→외장→내장 왕복 후 최종 맵 SHA-256까지 동일하다. 각 맵 옆 `.report.json`에 해시와 모드를 남겼다.
- 실게임 로딩·이미지 표시·멀티플레이는 미검증이다. 스크립트를 바꾸지 않았으므로 JASS 컴파일은 수행하지 않았다. 파일이 커진 만큼 실제 배포 경로와 게임 버전에서 다운로드/로딩을 확인해야 한다.
- 지원 범위는 ASCII 내부 경로와 로케일 0의 클래식 MPQ v0, 512바이트 HM3W 헤더다. 서명/알 수 없는 파일/목록 누락 등 지원 밖 입력은 중단한다.
- 기존 관리 대상 밖의 TGA/BLP 파일은 삭제하지 않았다. 이번 작업은 임의 리소스 정리를 하지 않는다.
