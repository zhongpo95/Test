# 전체 기능 호환 상태

v12는 완성본이 아닌 호환 시험본이다. 아래 항목 중 정적 검사나 모의 실행만 통과한 항목을 실제 플레이 성공으로 간주하지 않는다.

| 기능 | 현재 구현 | 남은 확인 또는 작업 |
|---|---|---|
| 초기화·Lua/JASS 연결 | JN 트리거와 네이티브 호출 연결 | 실제 헤라 진입과 선택 후 진행 |
| 모델·텍스처 | 보호 데이터 복원과 MH 경로 변환 | 실제 헤라 모델·초상화 렌더링 |
| 기본 UI·입력 | Dz 이미지·텍스트 프레임, 마우스·키보드 연결 | 연속 클릭·입력 차단·단축키·스크롤 |
| UI 특수 렌더링 | 기본 표시만 대체 | UV 자르기·반전, 부분 클리핑, 마스크, 회전, 셰이더 |
| 기본 효과 | 생성·부착·좌표·크기·속도·제거, 숨김/재표시 | 실제 전투 효과 표시와 수명 |
| 전용 효과 | 원래 기본 모델 유지 | 효과 모델 교체·색상·입자 크기, MDXS 애니메이션 |
| 게임 모드·구매·전투 | 원본 로직 유지 | 캐릭터 생성, 카드 구매, 웨이브, 보상까지 실제 검증 |
| 조준 입력 | 기본 엔진 명령 유지 | 원본 common_selector의 능력·명령·대상 종류 조회 |
| 멀티플레이 | 원본 동기화 경로 유지 | 복수 클라이언트 선택·구매·전투·이탈 검증 |
| 사운드 | Warcraft 믹서 연결 | 재생·중첩·볼륨·종료 확인 |
| 동영상 | 미지원 호출을 오류로 기록 | 별도 렌더/오디오 연결 |
| 중국 플랫폼 저장·계정 | 세션 메모리만 사용 | Hera 계정·저장 API에 맞는 별도 변환 설계 |

서버 저장의 계정과 접근 권한을 임의로 생성하지 않는다. KK DLL을 그대로 로드해도 JN의 Lua ABI와 게임 모듈이 같다는 보장이 없어 호환 DLL로 취급할 수 없다. DLL 구현은 각 함수의 호출 규약과 대상 런타임을 확인한 뒤 진행해야 한다.

다음 실제 확인 구간은 v12의 모드/난이도 선택 → 캐릭터 표시 → 카드 구매 → 첫 전투이다. 실패하면 해당 버전의 `Logs/Hera_Wanhua_v12_p1.txt`와 화면을 함께 비교한다. 로그의 `initialized; gameplay unverified`는 부트 반환 상태일 뿐 전체 게임 통과 표시가 아니다.
