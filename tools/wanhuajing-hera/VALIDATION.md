# v9 시험본 검사 기록

2026-09-22 생성한 시험본이며 실제 게임에서 정상 작동한다고 판정한 기록은 아니다.

v1은 사용자 실행에서 검은 화면과 `(null)` 반복 출력이 확인됐다. 이전 모의 검사는 JASS와 엔진 사이의 식 감싸기를 재현하지 못했다. 수정한 검사는 생성된 JASS의 `EXExecuteScript` 인수를 직접 읽고 설치 엔진과 같은 `return (...)` 형식으로 평가한다. v1 입력에서 `unexpected symbol near 'return'`을 재현했고 v2 입력은 통과했다.

v2는 실제 `Hera_Wanhua_v2_p1.txt`에서 `run.lua:33156: module 'jass.code' not found`, 모듈 23개·프레임 0개 상태가 확인됐다. 설치 DLL 모듈 목록에도 `jass.code`가 없다. 검사 환경의 가상 `jass.code` 모듈을 제거하자 같은 단계에서 중단됐고, 실제 맵 JASS 함수로 연결한 v3는 통과했다. 디버그 콘솔 자동 표시도 끄고 검사했다.

v3는 사용자 화면과 실제 `Hera_Wanhua_v3_p1.txt`에서 `run.lua:64215: attempt to call a nil value (local 'var_31014')`, 모듈 64개·프레임 0개 상태가 확인됐다. 모듈 860의 로더 변수는 `jass.message.origin_load`를 참조한다. YDWE `libs_message.cpp`의 `__newindex`가 `hook` 이외의 새 필드 대입을 무시하는 동작을 검사에 추가하자 같은 단계·같은 호출에서 실패했다. 후속 `wait` 오류도 기록되지만 첫 실패는 `origin_load`이다. v4는 호환 함수 5개를 `rawset`으로 등록하고 같은 대역에서 통과했다. 실제 설치 엔진의 이 메타테이블 동작을 별도 실행으로 조사한 것은 아니며, 소스·재현 결과와 사용자 로그가 일치한다.

v4는 사용자 화면과 실제 로그에서 `run.lua:51689: attempt to concatenate a nil value`, 모듈 153개·프레임 0개 상태가 확인됐다. 로그 경로가 v3 이름으로 고정돼 있어 `Hera_Wanhua_v3_p1.txt`에 기록됐다. 실패 지점은 `ui\loaded.fdf`를 읽어 누적 문자열에 붙이는 부분이다. 이 파일은 맵에 없으며, 로컬 저장값이 MPQ 읽기에 나타나지 않는 대역으로 같은 실패를 재현했다. v5는 원본 UI 정의를 맵에 포장해 실행 중 재읽기를 없앴다. 실제 저장 성공 여부와 네이티브 FDF 적용 결과는 이 검사만으로 확정하지 않는다.

v5는 실제 로그에서 초기화 완료(723개 모듈·프레임 1개) 이후 `unit_overhead` 누락과 `DzFrameSetEnable`의 `Call jass function crash.<TriggerEvaluate>`가 확인됐다. `2026-09-22 19.17.57/War3.dmp`는 `Game.dll+0x1E7DF0`의 `mov eax,[ecx+0xC]`에서 주소 0xC 읽기 위반을 기록했다. 두 오류가 관찰됐다는 근거이며, 해당 네이티브 호출이 최종 충돌의 단일 원인임을 입증하지는 않는다. v6는 문제 호출을 제거하고 기본 UI 템플릿·누락 함수·오류 후 중단 처리를 보완했다. 모의 검사의 해당 호출 오류는 로그에 근거한 주입 시험으로 실제 Game.dll 충돌 재현이 아니다.

v6는 사용자 스크린샷에서 기본 UI와 초록 전체 화면·흰 가장자리 효과가 확인됐다. 실제 로그에는 `run.lua:77729`의 render 미초기화, `52531`의 XLS_data 누락, 인수 없는 get_element_size 호출, common_selector 누락이 있다. 화면 그리기 요청을 추적하니 투명 이미지 `[UI]\空.png`가 로컬 `crop_v1_*.tga`로 바뀌어 전체 화면에 사용되고 있었다. 맵 내부에서 텍스처를 읽을 수 있어야 한다는 대역 조건을 추가하면 v6에서 `Texture is not in the map: HeraWanhua\crop_v1_3.tga`로 실패한다. v7는 잘라낸 이미지를 미리 포장하고, 검은 가장자리의 `u_rgb={0,0,0}`도 Dz 색상에 반영한다. 이 재현은 파일 경로 오류를 검출하며 실제 GPU의 초록 픽셀 출력을 재현한 것은 아니다.

v7는 실제 로그에서 26.271초에 PVE 모드, 29.491초에 초보 난이도 선택의 동기 수신이 완료됐다. 같은 시점 H000 플레이어 유닛 생성 후 `run.lua:52931`의 `SetUnitCollisionSize` 누락으로 초기화 이벤트가 중단됐고, `run.lua:80719`의 `SetPariticle2Size` 누락도 기록됐다. 두 호출을 원본 unit/effect_ex 메서드로 실행한 대역에서도 동일 오류를 확인했다. v8는 함수가 없을 때만 명시적 제한 처리를 제공한다. 동적 양수 충돌 반경과 입자 전용 크기 조절이 구현된 것은 아니며 기본 엔진 값을 유지한다.

v8의 실제 로그 `Hera_Wanhua_v8_p1.txt`는 11.921초의 초보 난이도 선택 이후 `run.lua:48192`에서 없는 소환 카드 풀을 순회한 오류를 기록한다. 건축사 등록 이벤트는 2.5초 뒤인데 레벨 변경은 즉시 발생한다. 이어 내부 5번 슬롯의 `has_save_permission`(`88459`)과 장식 설정 `get_save`(`35434`, 호출부 `96796`)도 중단됐다. 어댑터는 첫 오류부터 UI 갱신을 중지하므로 이 오류들은 화면이 멈추는 원인이다. 모델 미표시까지 이 오류만으로 설명할 수는 없다. v9는 원본 카드 풀 갱신 함수를 사용하고, 비플레이어 슬롯의 개인 권한·장식 조회를 생략한다.

UI 그리기 요청 중 문자열 조합으로 생성되는 WebP 27장·저장 UI 두 장이 변환 목록에서 빠져 있었다. 잘못된 확장자·폴더 세 개도 실제 파일에 연결했다. 검은 테두리용 변형은 RGB 0과 원본의 알파 바이트 일치를 확인했으며, 검정 착색 시 해당 변형을 선택하고 흰색 요청 시 원본을 선택하는 대역 검사를 통과했다. 실제 Dz BACKDROP의 착색 실패 원인을 확정한 검사는 아니다.

모델 의존성 조사는 미해결이다. 원본의 MDLX 1,537개에서 TEXS 경로 3,366개를 추출했으며 그중 MH 숫자 형식 3,029개는 해당 이름으로 원본 MPQ에서 찾지 못했다. 기본 게임 텍스처도 포함된 전체 경로의 단순 조회 실패 수를 누락 파일 수로 단정하지 않는다. 초기 건축사의 모델은 `-909478866.mdx`이며 두 TEXS 참조 `MH-819509167.blp`, `MH933634193.blp` 모두 원본과 v8에서 조회 실패했다. 이름이 확인되지 않은 BLP 블록은 보존돼 있지만 이 참조와의 연결을 확정하지 못했다. v9는 모델 복구 완료본이 아니다.
