# 로컬 Gemma 번역·사건 제작·검토 대화

Gemma 4 12B QAT을 이 PC에서 실행하는 프로젝트용 도구다. 번역, 사건·스토리 제작, 텍스트·이미지 검토 대화를 제공한다. Codex가 작성한 번역문이나 사건, 표지·삽화·게임 화면도 검토할 수 있다. 결과를 복사하거나 UTF-8 파일로 저장한다.

## 실행

1. 처음에는 `설치.cmd`를 실행한다. Ollama 실행 파일 약 1.46GB와 모델 약 7.2GB를 받는다. 실행 파일은 고정 버전 v0.35.0과 공식 SHA-256으로 검증한다. 모델 다운로드도 Ollama가 해시를 검증한다.
2. `시작.cmd`를 실행한다. [작업 화면](http://127.0.0.1:18765)이 브라우저에서 열린다.
3. 번역 모드에서 문장·아이템 설명과 용어집을 입력하고 목표 언어를 선택한다. 스크립트 전체 대신 번역할 텍스트만 입력한다.
4. 사건 제작 모드에서 세계관과 요청을 입력한다. 기존 `Data/Data_Prototype.j`의 해당 세계관 사건 일부를 참고하며, 원작 고증을 확인한 것으로 간주하지 않는다. 고정할 비용·보상·확률은 요청에 명시한다.
5. `이 결과 검토`를 누르면 생성 당시 요청·결과·용어집을 검토 화면으로 가져온다. `검토 시작`을 누른 뒤 후속 질문이나 수정본을 보내며 이어서 대화한다. 직접 만든 글이나 Codex 초안은 `초안 검토 · 대화`에서 원문·원래 요청과 초안을 붙여 넣는다.
6. 이미지는 검토 화면의 `검토 이미지`에 첨부한다. 글 없이 이미지와 원래 요청만 검토하려면 `프로젝트 이미지 검토`를 선택한다. 번역문·사건 초안 검토에도 이미지를 함께 넣을 수 있다. 후속 질문에 새 이미지를 첨부하면 수정 시안으로 비교한다.
7. 필요한 결과를 복사하거나 `초안 저장`·`자료·대화 저장`으로 저장한다. 초안은 TXT, 검토는 JSON으로 저장한다. 검토 JSON에는 최초 요청·초안·참고 설정·질문·답변과 첨부 이미지 데이터가 들어 있다. 복사는 이미지 파일명을 포함한 텍스트 대화만 복사한다. 전송한 요청은 자동 기록에도 남지만, 아직 보내지 않은 입력과 질문은 새로고침하면 사라진다. 새 초안은 필요한 대화를 저장하고 `새 검토`로 바꾼다.
8. 게임 시험 전에는 `GPU 메모리 해제`를 누른다. 완전히 닫을 때는 `종료.cmd`를 실행한다.

Windows 10 22H2 이상, Node.js 22 이상, NVIDIA 드라이버 551.61 이상이 필요하다. Node가 PATH에 없으면 Codex의 번들 Node 경로를 확인한다. 관리자 설치·로그인 자동 시작·시스템 환경 변수 변경은 하지 않는다.

## 모니터링과 자동 기록

화면 아래 `모니터링 · 처리 기록`은 브라우저와 CLI가 이 서버에 보낸 요청을 함께 보여 준다. 처리 중인 작업, 경과 시간, 이미지 수, 모델 설치·적재 상태, Ollama가 보고한 모델 GPU 메모리와 컨텍스트를 3초마다 갱신한다. 숨겨진 탭은 10초마다 갱신한다. 모델이 준비되기 전에는 적재·준비 중으로 표시한다. 진행률 백분율과 GPU 전체 사용률은 제공하지 않는다.

각 기록에는 시작·완료 시각, 성공·실패·중단·시간 초과, 전체 경과 시간과 모델 응답 시간·생성 속도가 남는다. `기록 보기`에서 요청·초안·질문·이전 대화·첨부 이미지·답변과 오류를 확인하고 `기록 JSON 저장`으로 내보낼 수 있다. 검토는 매 요청 당시의 전체 대화를 기록하므로 후속 질문에도 최초 자료와 이전 이미지가 들어 있다. 모델 서버가 끊겨도 화면 서버가 실행 중이면 기록을 조회할 수 있다.

자동 기록은 `%LOCALAPPDATA%\ArcanaGemma\records`에 보관한다. 새로고침하거나 화면·서버를 닫아도 파일은 유지된다. 서버가 처리 도중 종료되면 다음 시작에 해당 요청을 `서버 종료`로 표시하며 성공으로 추정하지 않는다. 최대 100건 또는 128MiB까지 보관하고 한도를 넘으면 오래된 완료 기록부터 정리한다. 계속 보관할 자료는 별도 JSON으로 저장한다. 저장·읽기가 실패하면 패널에 알리며 모델 결과는 반환한다.

모니터링 추가 후 서버에 전송한 요청부터 기록한다. 이전에 저장하지 않은 대화는 복구되지 않으며, Ollama를 직접 호출한 요청도 이 패널에 기록되지 않는다. 화면의 작성 칸을 자동 복원하거나 기록에서 대화를 이어 여는 기능은 없다. 기록 JSON은 조회용 구조(`input`, `result`)이므로 검토 CLI에 그대로 넣는 형식은 아니다. CLI에서 이어가려면 `input`의 최초 조건·이력에 성공한 이번 질문과 답변을 더하고 새 `text`를 지정한다.

## Codex와 터미널에서 검토 요청

작업 화면 서버가 실행 중이면 브라우저 조작 없이 같은 검토 모델을 호출할 수 있다. 프로젝트 루트에서 다음 명령을 실행한다.

```powershell
node tools/local-gemma/review.cjs tools/local-gemma/검토요청예시.json
```

[검토 요청 예시](검토요청예시.json)의 `kind`는 `translate`, `story`, `image`, `brief`는 원문·최초 요청, `draft`는 초안, `text`는 검토 질문이다. 번역은 `language`(ko/en/zh/ja), 사건은 `world`(academy/penacony/scarlet/original)를 지정한다. `glossary`에는 용어집·참고 설정·검토 기준을 넣는다. 예시는 일부러 보상·비용·파티 자원 조건을 틀리게 만든 사건이다.

이미지는 [이미지 검토 예시](이미지검토요청예시.json)처럼 `imagePaths` 배열에 PNG·JPEG 경로를 넣는다. 상대 경로는 요청 JSON 파일의 폴더를 기준으로 해석한다. CLI는 파일당 4MB, 가로·세로 각각 2,048px 이내인 자료를 받으며 자동으로 줄이지 않는다.

```powershell
node tools/local-gemma/review.cjs tools/local-gemma/이미지검토요청예시.json
```

응답 JSON에는 검토 문장과 이미지 데이터를 포함한 `history`가 들어 있다. 후속 검토는 최초 요청 파일의 `brief`·`draft`를 유지하고 응답의 `history`를 넣는다. `text`에는 질문·수정본, `imagePaths`에는 새 수정 이미지 경로만 넣는다. 이전 이미지는 `history`에 있으므로 다시 첨부하지 않는다. 응답 전체를 그대로 요청으로 쓰면 최초 자료가 빠지므로 원래 요청과 합쳐야 한다. 화면의 `자료·대화 저장`으로 받은 JSON은 최초 자료와 이력을 포함하므로 CLI에서 이어 쓸 수 있다. 질문·답변 6쌍이나 자료 예산을 넘으면 새 검토가 필요하다. CLI는 파일을 읽고 응답을 출력하며 초안과 이미지 원본을 자동 수정하지 않는다.

## 구성과 한계

- 모델과 실행 로그는 `%LOCALAPPDATA%\ArcanaGemma`에 저장된다. OneDrive와 Git에 대용량 모델을 넣지 않는다.
- 전용 Ollama는 `127.0.0.1:11435`, 작업 화면은 `127.0.0.1:18765`에서만 수신한다. `OLLAMA_NO_CLOUD=1`로 클라우드 기능을 끄고 모델명을 서버에서 고정한다.
- 원격 추론, 파일 편집, 코드 실행 도구는 연결하지 않는다. Gemma의 답변은 텍스트로만 표시된다. 직접 적은 요청이 용도를 벗어난 답변을 유도할 가능성까지 모델 수준에서 막는 것은 아니다.
- 입력은 4,000자, 용어집은 1,500자로 제한한다. 컨텍스트 8,192토큰, 출력 최대 3,072토큰, 동시 생성 1개, 요청 제한 5분이다. 긴 글은 나눠 입력한다. 출력이 잘리면 오류로 알린다.
- 검토에서는 최초 요청·초안 각각 4,000자, 질문·수정본 1,500자까지 받는다. 최초 자료·시스템 기준·이전 대화·현재 질문을 합친 UTF-8 텍스트가 12,000바이트를 넘거나 질문·답변 6쌍을 마치면 새 검토를 안내한다. 대화를 조용히 잘라내지 않는다. 검토 컨텍스트는 16,384토큰, 출력 최대 2,048토큰이다. 입력 예산과 출력 여유를 따로 남긴다.
- 이미지가 있으면 텍스트 예산에서 이미지당 2,240바이트를 추가로 남긴다. 첫 이미지와 후속 이미지 총 3장까지 유지하며 이미지나 대화를 자동으로 버리지 않는다. 모델이 이미지를 처리하는 토큰 예산의 실제 적용은 Ollama에 맡긴다.
- 화면 첨부는 PNG·JPEG·WebP 원본 10MB 이내이며, 긴 변을 최대 2,048px로 축소하고 WebP는 PNG로 변환한다. 전송본은 파일당 4MB 이내다. 원본 파일은 바꾸지 않는다. 작은 글씨는 확대한 부분 이미지를 추가하는 편이 낫다. 서버는 PNG·JPEG 데이터의 형식·크기·해상도를 확인하고 외부 이미지 URL을 받지 않는다.
- 첫 검토 후 최초 자료가 고정되며 후속 질문과 수정본을 추가한다. 모델은 매 요청마다 최초 자료와 대화 내역을 함께 받는다. 작성 중 대화는 브라우저 메모리에, 전송한 요청의 자료·답변은 서버의 자동 기록에 남는다. 검토 대상 변경에는 `새 검토`를 사용한다.
- 번역의 색상 코드, `|n`, `|r`, 실제 줄바꿈, 숫자, `{변수}`, `%s`/`%d`, `'I0CC'` 형태 rawcode와 영문 경로는 출력 후 원문과 대조한다. 서식의 순서가 바뀌거나 값이 누락·변경·중복되면 결과를 거부한다. 번역 어순에 따른 변수 위치 이동은 허용한다. 임의의 JASS/Lua 식별자나 모든 포맷 문법을 보존하는 소스 번역기는 아니다.
- 일반 번역은 낮은 온도 0.1, 사건 초안은 0.8로 생성한다. 한국어 자연스러움·장편 연속성·원작 고증·밸런스는 사람의 검토가 필요하다. 소형 모델의 초안을 최종 확정 문장으로 간주하지 않는다.
- 검토 온도는 0.1이다. 요청 준수·번역 의미·문장·선택·비용·보상과 이미지의 구성·가독성을 평가하지만, 빠뜨리거나 과도하게 지적할 수 있다. 이미지의 작은 글씨와 변경 여부도 잘못 읽을 수 있다. 모델의 `사용 가능`은 원작 고증·밸런스·실제 게임 동작의 검증 통과가 아니다.
- 번역문 검토의 서식·수치 검사는 처음 초안을 대상으로 프로그램이 별도로 계산한다. 틀린 초안도 검토를 허용하고 누락·추가·서식 순서 변경을 표시한다. 후속 수정본의 의미와 서식 평가는 대화 모델의 답변이며, 화면의 `처음 초안의 서식·수치 검사`는 후속 문장에 대한 재계산 결과가 아니다.
- 이미지 속 문구는 모델이 읽으며 프로그램의 서식·수치 대조 대상이 아니다. 정확한 수치 대조가 필요하면 원문과 번역문도 텍스트 칸에 넣는다.
- 요청을 마친 모델은 2분 뒤 자동 해제한다. 중단 버튼은 서버의 모델 요청도 취소한다. 화면을 닫아도 서버는 유지되므로 `종료.cmd`로 닫는다.
- 종료는 이 도구가 기록한 PID·실행 경로·시작 시각이 모두 일치하는 프로세스만 대상으로 한다.

## 검증

`node --test tools/local-gemma/check.cjs`는 실제 HTTP 서버와 모의 모델 응답으로 호출 제한, 서식 보존, 검토 자료와 대화 유지, 이미지 전달·검증·예산, 역할·대화 한도, 잘린 답변, 동시 호출, 메모리 해제를 검사한다. 모니터링은 진행 상태·완료 기록, 이미지와 이력 보관, 재시작 복구, 인증과 경로 제한, 모델 연결 실패, 저장 실패, 100건·용량 한도 정리를 검사한다. 실제 Gemma 출력과 속도는 별도 [검증 기록](검증기록.md)에 구분해 적는다.
